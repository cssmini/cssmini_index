      2026-03-18 プロジェクト

      1.1 プロジェクト名：E入職（E-Register）

      紹介

      「E入職」は、企業と入社予定者向けのスマート入社手続きプラットフォームです。HR はワンクリックで履歴書をインポート・自動解析し、入社招待を送信できます。入社予定者はモバイル端末で手続きを完了できます。中核機能は動的入社情報フォーム（Dynamic Onboarding Form）で、企業が入社タイプや勤務地などの条件に応じてフォームフィールド（テキストボックス、選択ボックス、画像アップロード等）をカスタマイズ設定できます。フィールド間の連動表示（例：特定選択肢選択時に追加フィールドを表示）もサポートしています。

      プロジェクト使用技術

      • バックエンド (Backend)：Spring Boot 2.2.10、Spring Data MongoDB、Redis (Jedis 3.1.0)、Fastjson 1.2.83
      • フロントエンド (Frontend)：Vue 2.5.2、Vue Router、Vuex、Vux 2.9.2（モバイル）、Node 6+
      • データベース (Database)：MongoDB（JSON 形式でデータ保存）
      • 外部連携：企業微信 (WeCom)、E人事 (E-HR)、Moka 採用システム

      プロジェクトでの役割

      本プロジェクトのフロントエンド・バックエンド両方の保守、新規要件開発、テスト、ビジネスロジック調査、運用保守を担当。

      業務のハイライト

      • テンプレート変換機能（集团字段分离及模板转换）：最も難易度の高い要件。既存入社データを新テンプレートに変換し、ユーザーが入力済みのデータを保持する。数十種類のフィールドタイプ（input, select, selectWithParent, group）に対応し、自動マッチング＋手動ペアリング機能、17 項目に及ぶ厳密なデータ検証ロジック（連動 Select の親子関係整合性、グループ型の配列データ処理等）を実装。連動 Select → 連動 Select、連動 Select → 通常 Select、通常 Select → 連動 Select、繰り返し可能グループ型など、複雑なフィールドタイプ間のデータ移行ロジックを完全実装。
      • 26 種類の外部同期タスク：テナント情報、組織アーキテクチャ、管理者情報、企業微信アドレス帳、E人事辞書・職級データ等の定期同期ジョブを管理。
      • 50 件以上の要件対応：バッチ入社招待発行、バッチ知会メール、ID 番号検証（生年月日クロスチェック）、工カード写真仕様検証、銀行・勤務地の動的表示制御、ログイン認証ゲートウェイ対応等。
      • Moka 採用システム API 連携：入社状態同期、データ提供インターフェースの開発。

      1.2 プロジェクト名：案例中心（Case）

      紹介

      Tencent 学堂（Q-Learning）傘下の社内ナレッジ共有プラットフォーム。テーマ別のアンケート方式で特定分野の知見を収集し、他社員が検索・閲覧できます。PC 版・モバイル H5 版を提供し、企業微信ワークベンチと WeChat ミニプログラムにも統合。企業微信メッセージ通知サービスと連携し、コメント・いいね・新着ケースをプッシュ通知します。

      プロジェクト使用技術

      • フロントエンド (Frontend)：Angular 4.3.5、Webpack 2.6.1、TypeScript、Less/Sass
      • バックエンド (Backend)：flydiy-base（Spring Boot ベースの社内分散フレームワーク）、Spring Boot 1.5.10、Undertow
      • 外部連携：企業微信メッセージ通知、情報セキュリティ審査サービス

      プロジェクトでの役割

      フロントエンド開発エンジニア。要件開発、問題調査・バグ特定、ビジネスロジック調査、ユーザーからの問い合わせ対応。

      業務のハイライト

      • 情報セキュリティ審査機能の全面導入：全フォーム送信箇所に情報セキュリティ審査サービスを統合。文字・画像のセンシティブ情報チェックを実施し、違反時は送信不可とする。全フォームに規約同意チェックボックスを追加。
      • UGC 投げ銭機能の実装：Tencent 学堂の投げ銭サービスと連携。固定額＋カスタム額の投げ銭 UI、ポイント残高チェック、ポイント不足時の制御を実装。
      • 大規模言語モデル連携：コンテンツに「小 Q 同学（AI チャットボット）への同期可否」フィールドを追加。
      • 未読メッセージリマインダー：PC 版・モバイル版のアバターに赤いバッジ通知を実装し、企業微信と連携。
      • OA ドメインから WOA ドメインへの移行：全リンクと設定の一括変更対応。

      1.3 プロジェクト名：新行家（eShifu）

      紹介

      Tencent 学堂傘下の社内エキスパート相談プラットフォーム。社員は「行家」（エキスパート）として申請入驻し、他社員から特定領域の相談を受けることができます。相談には QLearning ポイント（年 2000 ポイント付与）を消費し、獲得ポイントは給与に交換可能。1 対 1、1 対 3、1 対 6、1 対 10+ の相談形式をサポートしています。

      プロジェクト使用技術

      • フロントエンド (Frontend)：Angular 4.3.5、TypeScript、TinyMCE 4.8.3
      • バックエンド (Backend)：flydiy-core V2（Spring Boot 2.1.8 ベース）、Spring Data Redis、Spring Cloud Netflix（Eureka、Feign、Hystrix、Ribbon）
      • 外部サービス：企業微信、メール (EWS Java API)、Tencent Cloud COS、QR コード (ZXing)、バーコード (Barcode4j)、Excel 出力 (EasyExcel)、PDF 生成 (PDFBox)
      • その他：Hutool 5.7.16、Lombok、Fastjson 2.0.25

      プロジェクトでの役割

      PC 版・モバイル版のフロントエンド開発全般、要件開発、問題調査を担当。

      業務のハイライト

      • 1 対多相談システムへの大改造：1 対 1 のみだった相談形式を 1 対 3、1 対 6、1 対 10+ に拡張。トップページ、個人センター、話題検索結果リスト、分類ページなど全画面を改修。話題排期管理の可視化インターフェースを追加。
      • 情報セキュリティ審査対応：全フォームに情報セキュリティ審査サービスを統合。
      • 大規模言語モデル連携：コンテンツに「小 Q 同学」同期可否フィールドを追加。
      • フロントエンドアーキテクチャ改善：npm ソース変更、node-sass バージョン互換性問題解決、パイプライン自動デプロイ対応。
      • 2 年以上にわたる継続的改善：ポイント割引設定、課酬管理、通知センター、相談カレンダー、カウントダウン機能、1VN 排期管理など数十件の機能開発。

      1.4 プロジェクト名：学堂対外課程申請平台（Academy）

      紹介

      オフライン講座・イベント予約システム。全国の Tencent オフィスビル（深圳 Tencent 大厦、深圳滨海大厦等）の教室リソース予約をデジタル化管理。Tencent 学堂・Tencent 教室ライブ配信サブプロジェクトと連携し、オンライン・オフライン同時授業をサポート。外部企業にも開放されています。

      プロジェクト使用技術

      • フロントエンド (Frontend)：Vue 2.6.10、Vue Router、Vuex、Element UI 2.15.13、@tencent/sdc-core / sdc-vue / sdc-webui（社内 UI コンポーネントライブラリ）、TinyMCE 5、Date-Time-Picker-Pro
      • ビルドツール (Build)：Vue CLI 4.1、Less、PostCSS、SVG Sprite
      • バックエンド (Backend)：テスト環境の API に接続（バックエンド開発には未参加）

      プロジェクトでの役割

      プロジェクトチームの人員不足により、フロントエンド開発および要件調整を代行担当。

      業務のハイライト

      • プラットフォーム全面アップグレード：UI フレームワーク刷新を含む大規模改修（全ページ改修、TinyMCE エディタ統合、社員選択コンポーネント差し替え）。
      • 費用表示の動的制御：費用合計を「期間限定無料」表示に変更するロジックを実装。

      1.7 プロジェクト名：薪雲給与明細（PayRoll-XinYun）

      • 権限制御の強化：ボタンレベルの表示/非表示制御（退職者給与明細送信ボタン等）。権限設定不備時のフィードバック改善。

      • タイミング公開機能：給与明細のタイミング公開（予約公開）機能のフロントエンド実装。

      1.9 プロジェクト名：産陪生双選（Q-Career）

      紹介

      Tencent プロダクトマネージャー研修生（産陪生）の面接相互選択 WeChat ミニプログラム。研修終了後、学生と指導者間の相互選択面接に使用。プロセス：（1）学生が希望ポジションを選択し履歴書を提出（3 件まで、ロック後変更不可）、（2）指導者が履歴書に基づき学生を 3 名選択、（3）管理者がマッチングデータをインポートし面接開始、（4）面接終了後面接結果を確認。

      プロジェクト使用技術

      • フロントエンド (Frontend)：WeChat ミニプログラム
      • バックエンド (Backend)：Tencent Cloud データベース、Tencent Cloud 開発 API

      プロジェクトでの役割

      プロジェクト開発・保守担当。

      業務のハイライト

      • データメンテナンス：相互選択期間中の初期データインポート、選択結果エクスポート等の運用対応。

      1.10 プロジェクト名：商業保険理賠（Insurance）

      紹介

      Tencent 商業保険オンライン保険金請求システム。HR 福利厚生・報酬部門が従業員の保険金請求業務をデジタル化するために立ち上げ。従来の紙ベース申請に加え、オンライン申請機能を追加。内部ネットワークのモバイル端末（保険金請求申請・状態追跡・保険情報照会）、内部ネットワークの PC 運用端末（統計・保険情報管理・設定管理）、外部ネットワークの保険会社向け API（保険金請求情報同期・審査状態同期）の 3 つの主要部分で構成されています。

      プロジェクト使用技術

      • フロントエンド (Frontend)：React 16.4.2、React Router 4.3.1、Redux、Ant Design 3.9.4、ECharts 4.2.0、TinyMCE 5.0.9（PC 版）、Webpack 3.8.1（モバイル版）
      • バックエンド (Backend)：（担当範囲外）
      • インフラ (Infrastructure)：Linux CentOS、MySQL、Tencent Cloud デプロイ

      プロジェクトでの役割

      PC 版・モバイル版のフロントエンド開発全般。要件開発、問題調査、システム保守を担当。

      業務のハイライト

      • 保険金請求書類サンプル画像の動的設定：管理画面からサンプル画像を設定可能にし、モバイル側で動的表示する機能を実装。
      • 文書・サンプル画像の動的調整：「検査・化验報告書」の文書とサンプル表示ロジックを刷新。
      • 保険会社自動マッチングロジック変更：契約保険会社の自動マッチングルールをビジネス要件に合わせて改修。
      • 本人確認検証ルール追加：モバイルページ閲覧時に本人確認検証を追加。
      • 画像アップロード不具合の根本原因調査：特定端末で画像アップロードが失敗する問題の詳細調査と対応。
      • AI アシスタント連携：保険金請求モバイル端末に「小 T 助手」を統合。

      1.11 プロジェクト名：直播管理システム（Q-Live）

      紹介

      Tencent 学堂サブシステム、ライブ配信モジュール。Tencent ライブ配信プッシュと接続し、PC・モバイルでのライブ配信視聴機能を提供。視聴者端末、講師端末、管理端末の 3 つのロールで機能を区別。ライブ配信プッシュ、弾幕、ギフト投げ銭、抽選インタラクション（弾幕抽選、クイズ抽選、通常抽選、アンケート抽選）、新規ユーザー参加時の弾幕通知等の完全なライブ配信機能を提供。外部のライブ配信予約システム向けに予約データ書込 API を提供。

      プロジェクト使用技術

      • フロントエンド (Frontend)：Vue.js（PC 管理端末、PC フロントエンド）、WeChat ミニプログラム（視聴端末）
      • バックエンド (Backend)：Node.js

      プロジェクトでの役割

      Node.js バックエンド開発エンジニア。

      業務のハイライト

      • 抽選機能の拡張：アンケート参加型抽選方式を追加。単一選択クイズ抽選、複数選択クイズ抽選、アンケート抽選の 3 種類を新規実装。投票比率計算（小数点第一位まで）を含む集計ロジックを実装。
      • データウェアハウス向け全量データ API：Tencent 学堂親プロジェクトのデータウェアハウスに全量データを提供するインターフェースを設計・実装。
      • 抽選重複排除ロジック最適化：同一ライブ配信内で既に当選したユーザーを除外し、管理者がオン/オフ切替可能なスイッチ制御を実装。
      • ライブ配信予告リスト最適化：予約システムとのデータ同期 API を最適化。

      1.12 プロジェクト名：E計画（E-Project）

      紹介

      Tencent 社員・管理職・組織アーキテクチャ管理プロジェクト。Tencent 人事リソースプラットフォーム（hr.oa.com）に属する基盤レベルの人事管理システム。細粒度の組織アーキテクチャ・人事管理（組織変更、人員異動等）を提供。会社発文（Policy）プロジェクトと連携し、管理職の組織変更を公示。組織アーキテクチャの対外 API を提供し、Tencent 社内の全組織アーキテクチャデータの唯一のソースとして機能。

      プロジェクト使用技術

      • フロントエンド (Frontend)：HTML、CSS3、JavaScript、jQuery 1.11.0、jQuery UI、zTree 3.5
      • バックエンド (Backend)：.NET

      プロジェクトでの役割

      フロントエンドプロジェクト保守、要件テスト、要件開発、ビジネス機能ロジック調査を担当。

      業務のハイライト

      • 組織調整業務フローの最適化（E計画二期）：組織調整時のメール送信有無の選択ポップアップ、共通プロンプトボックスの書き直し（スタイル調整含む）、報告ライン上位ポジション検証ロジック追加。
      • 組織英文名称一括インポート機能：ファイルアップロード機能の追加。
      • 管理主体（Management Entity）機能強化：空値検証、テンプレート修正、検索不具合の修正。
      • 仮想組織カテゴリ追加：仮想組織タイプの追加と関連フィールドの調整。
      • 一括コピー＆ペースト機能：製品サブプロジェクト情報の一括コピー＆ペースト、データ行の一括追加・削除。
      • その他：オフライン組織ハンギング機能、操作動画再生不具合調査、組織選択不可問題の修正等。

      1.13 プロジェクト名：会社発文（Policy）

      紹介

      Tencent 社内政策・規則管理システム（policy.woa.com）。政策規則の審査管理、公布、公示、有効期限公示、政策詳細内容閲覧、政策規則検索等、会社政策に関する全機能を提供。会社の公式政策発表チャネルであり、「公文」業務——オンライン起案 → 審査 → 公開の流れで運営されます。制度文書、組織文書、事務文書、公告文書の 4 種類に分類。PC 版・モバイル版は同一コードベースでレスポンシブ対応。

      プロジェクト使用技術

      • フロントエンド (Frontend)：Vue 2.6.10、Less、ESLint
      • バックエンド (Backend)：Java、Spring Boot、MySQL 8.0
      • ビルドツール (Build)：IDEA、VSCode

      プロジェクトでの役割

      フロントエンド開発エンジニア。2024 年 8 月から 2025 年 8 月までの全フロントエンド関連の要件開発・ビジネスロジック調査を担当。

      業務のハイライト

      • 制度鮮度保持プロジェクト（制度保鲜专案）：発文の定期的見直し・廃止フロー最適化の専任プロジェクト。移入・移出ポップアップの未検索時「確定」ボタン無効化、廃止フローの抜本的改善、一覧ページの複数不具合修正（公開機関のコンポーネント長異常、未公開文書の起案ページでの「改訂」「廃止」メニュー非表示化、ホワイトリスト保存エラー等）。
      • 廃止フロー最適化：廃止ボタンクリック後のポップアップ表示から廃止フロー全体を刷新。公開ページの初期化問題を修正。
      • SDC-UI アップグレード：社内 UI コンポーネントライブラリのバージョンアップ対応と不具合修正。
      • メール設定機能改善：メール設定ページへのガイダンス説明追加、メールアドレスのスペース検証追加。
      • 国際化対応：添付ファイルの国際化英語表示修正。
      • 文書タイトル表示・フォント不具合修正。

      1.14 プロジェクト名：雲休暇（Yun Holiday）

      紹介

      Tencent 社内の従業員休暇管理・審査システム。休暇申請審査フロー管理、休暇残高管理（年次休暇、福利休暇、育児休暇、振替休暇等）、従業員情報管理（E計画プロジェクトからのデータ同期）、通知メッセージ照会（メール・企業微信・SMS）、休暇通知リマインダー（テンプレート設定・対象組織範囲設定・通知頻度設定・メール内容設定）、休暇タイプ設定（産休・育児休暇・年休等の個別設定、給与計算方式設定、適用組織範囲設定）、休暇カレンダー設定（法定休日の可視化設定）、審査フロー設定、残高ルール設定（個人の勤続年数に応じた残高計算、有効期限管理、未使用残高の給与換算可否）、消暇ルール設定（正常消暇・非正常消暇・休暇取消・休暇タイプ変更）、管理者権限設定（メニューレベルの細粒度権限）。中国国内版・海外英語版の 2 バージョンを展開。給与システムへのデータ提供 API を提供。Vue I18n による国際化（中国語・英語切替）対応。

      プロジェクト使用技術

      • フロントエンド (Frontend)：Vue 2.0、Vue I18n 8.21.1、Axios、Element UI 2.15.6、Less、Webpack 2.2.1
      • バックエンド (Backend)：Go 言語

      プロジェクトでの役割

      フロントエンド開発エンジニア。2022 年 2 月から 2023 年 9 月までの本プロジェクト関連の要件開発・業務調査を担当。

      業務のハイライト

      • 包括的な休暇管理機能のフロントエンド実装：消暇規則設定モジュールの新規追加、審査ノードでの部門選択機能、休暇タイプによる審査プロセス分岐、期限切れ間近の残高休暇タイプ向けカスタムリマインダー（期限前の日数と通知頻度を設定可能）、添付ファイルアップロード付き審査、全申請内容・審査過程の閲覧機能。
      • コンポーネント不具合修正：社員選択・部門選択コンポーネントの位置ずれ問題の修正とデバッグログ追加。
      • 国際化対応：Vue I18n を用いた中国語・英語画面切替の実装。

      1.15 プロジェクト名：ワンクリックカバー（SDC-Img-Cover コンポーネント）

      紹介

      Tencent SDC ビジネスライン向け汎用「ワンクリックカバー生成」コンポーネント。低コード侵入設計で、プロジェクトが迅速にカスタムカバー生成サービスを導入可能。智絵学堂サービスと API 連携し、カバーコンテンツ、ロゴ、背景、人物画像、イラストをアップロードしてカバーを自動生成。@tencent/training-components コンポーネントライブラリの 1 コンポーネントとして npm パッケージで配布。

      プロジェクト使用技術

      • フロントエンド (Frontend)：Vue.js
      • パッケージ管理 (Package)：Tencent npm レジストリ（@tencent/training-components / @tencent/training-components-beta）
      • 外部連携：智絵学堂（画像生成サービス）

      プロジェクトでの役割

      コンポーネント開発・メンテナンス担当。

      業務のハイライト

      • コンポーネント化により、各プロジェクトが智絵学堂サービスを個別にドキュメント参照・API 連携する手間を解消。数行のコードで導入可能なカプセル化を実現。
      • npm パッケージ配布フロー（beta → master）に沿ったリリース管理。

      1.16 プロジェクト名：オンライン講師システム（Lecture Proj）

      1.17 プロジェクト名：在職核查（OnlineCheck）

      紹介

      従業員出勤・在崗データ核查プロジェクト。毎月の人事部門による出勤計算に使用。E 計画人事システムとデータ連携し、従業員データのソースとして使用。従業員の打刻データ、会社ゲート入退記録、食堂 IC カード決済記録、打刻端末、社内バス IC カードデータを管理。

      プロジェクト使用技術

      • .NET WebApp プロジェクト（Java WebApp に類似、JSP のようなサーバーサイドレンダリング + Ajax）
      • バックエンド (Backend)：.NET、SQL Server
      • フロントエンド (Frontend)：HTML、JavaScript、jQuery、Ajax

      プロジェクトでの役割

      HTML ページ開発、JS インタラクションロジック開発を担当。.NET 担当者の協力を得てローカル開発環境を構築し開発テストを実施。

      業務のハイライト

      • システム設定ページのフロントエンド実装：勤務地・管理主体の設定ページを新規開発。
      • 旧式 Web アーキテクチャ（.NET WebApp）における HTML → サーバーサイドテンプレート変換 → JS ロジック開発のフローを理解した上での開発対応。

      1.18 プロジェクト名：製品人力棚卸（PMI）

      紹介

      Tencent 事業製品の人的リソース管理システム。人的リソース配置の可視化・デジタル化を実現。従業員の日々の作業時間投入先（プロジェクト、プロジェクトチーム単位）、各プロジェクトの人的投入データを管理。毎週各プロジェクトチームがボトムアップでデータを収集し、人事担当者がプロジェクトを親項目としてデータをシステムに登録。四半期ごとに人的リソース投入の棚卸を実施。

      プロジェクト使用技術

      • フロントエンド (Frontend)：Vue 1.0.26、Vue Resource 0.9.3、Vue Router 0.7.13、Vuex 1.0.0-rc.2、Webpack 1.13.1、Sass/SCSS
      • バックエンド (Backend)：.NET、T-SQL、SQL Server 2019、Redis 5.0.10
      • その他：Visual Studio 2019、Node.js 14.15.4

      プロジェクトでの役割

      プロジェクトチームの人員不足により、一時的に本プロジェクトの要件開発を担当。

      業務のハイライト

      • 一括コピー＆ペースト機能：製品サブプロジェクト情報の一括コピー＆ペースト機能を実装。
      • データ行の一括追加・削除：テーブルデータ行の一括追加・削除機能を実装。
      • 却下データの削除不可制御：審査却下されたデータの削除を不可とする制御を実装。
      • 照会進捗ページ最適化：メール送信機能を含む進捗照会ページの改善。
      • 製品設定ページ改修。

      1.19 プロジェクト名：ブロックチェーンクリッパー（Blockchain Sniper）

      紹介

      BSC チェーンのハッシュデータ監視ツール。指定コントラクトの大口取引を検知し、Gas 代が高いほどノードにより早く書き込まれる原理を利用して、大口取引より先に買い注文を入れ、大口取引成立後の価格上昇時に即座に売却して差額を獲得するフロントランニングボット（Front-running Bot）。

      プロジェクト使用技術

      • JavaScript、PancakeSwap API、BSC ブロードキャストソース

      プロジェクトでの役割

      個人研究開発プロジェクト。

      業務のハイライト

      • BSC チェーン上のトランザクションデータ監視ロジックの研究と実装。
      • PancakeSwap DEX の API を利用した取引執行の自動化。
